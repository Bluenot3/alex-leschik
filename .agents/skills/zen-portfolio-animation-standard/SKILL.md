# ZEN Portfolio Animation Standard

Treat the supplied source as the technical and visual baseline, not as inspiration for a generic approximation. Build comparable craftsmanship with demonstrable performance; do not promise identical quality on every device or claim model authorship without evidence.

## Scope and inputs

- Use the current target project/section and the user's requested effect. Infer missing colors, content, and scale from that project's design system; ask only when an expensive choice cannot be inferred.
- Creating or updating this skill does not authorize any change to the source portfolio, its graphics, or its publication.
- Reuse mechanics, not Alex's biography, claims, project names, logos, private data, or hidden mottos in unrelated products. Brand assets in the source snapshot are reference-only until authorized for that target.

## Start with zen-foil

If the request is a plate the zen-foil kit already draws (seal, globe, U.S. map, banner, certificate, metric, agent network, engraved photo, image stage, crystal cube, glyph background, or one of the 20 portfolio plates), use the `zen-foil` skill instead: read `skills/zen-foil/AGENTS.md`, write tags with `scripts/replicate.mjs`, and check them with `scripts/verify.mjs`. That is one script tag and a checked element, not a copied engine. Use this skill for what the kit can't do: new motifs, engine work, or effects outside the plate format.

## Read before building

- Read [aesthetic.md](references/aesthetic.md) for every use: it defines the actual material language and the standard for a stronger variation.
- Read [integration.md](references/integration.md) when implementing an effect: it maps working source, dependencies, uniforms, and safe adaptation.
- Read [verification.md](references/verification.md) before claiming completion: it defines the visual, fallback, and scrolling checks.
- Read only the relevant bundled source under `assets/source/`, as directed by the integration reference. Do not blindly transplant the entire snapshot or import from a skills directory at runtime.

## Workflow

1. Inspect the target's typography, semantic tokens, section dimensions, interactive controls, existing clocks, and graphics load. Identify a fixed footprint and unobstructed reading areas before choosing motion.
2. Choose a meaning-bearing motif from the aesthetic reference and a relevant real shader. Explain the composition internally in one sentence: subject, material, time behavior, input response. Avoid unrelated particle clouds, neon blobs, generic orbital rings, or random dashboards.
3. First reproduce a working baseline from the source with the same antialiasing, material, interaction, and fallback behavior. Then change one principal dimension—geometry, temporal choreography, or contextual input—to make the target original.
4. Copy only the required dependency closure into the target project. Resolve imports, fonts, marks, semantic palette, and capabilities. Preserve existing content, routes, layout order, actions, and business rules unless explicitly requested otherwise.
5. Use one shared animation clock and shared graphics resources. Reserve layout before initialization; render the readable static/poster state first. Never block the page on a decorative shader compiling.
6. Verify the complete experience, including missing GPU support and reduced motion, using the verification reference. Refine until the new composition is perceptibly better without obscuring the subject or worsening usability.

## Delivery

Report the visible result and any verified limitations briefly. Describe source-derived craft honestly. Publish only when requested. If the task is skill extraction only, activate the completed skill and leave the application untouched.
